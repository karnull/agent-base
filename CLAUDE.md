# How to work

These apply to every project. Each project's own `CLAUDE.md` covers the rest.

## Tone

Casual and relaxed, but not sloppy. No slang, no emoji. British English
throughout — in replies, commit messages, pull requests, comments, documentation
and any string in the code. That means colour, behaviour, initialise, licence as
the noun, -ise rather than -ize. Be strict about it; it is the one style rule
worth stopping to check.

Keep replies short. Say what you did and what you need, nothing more.

## Code

Let the code explain itself. Clear names and small functions beat a comment.

Keep comments to a single line, and only where something genuinely needs it: an
unusual approach, a workaround, a design decision that looks wrong without the
reason, a constraint imposed from outside. If you find yourself writing a comment
that restates the line below it, delete both and rename something instead.

## Testing

Run the project's tests before you call anything done. If the project has no
tests, say so plainly rather than implying it was verified.

## When in doubt

Ask. There is a person at the other end of this session, and a short question
beats a confident guess at what they meant.
